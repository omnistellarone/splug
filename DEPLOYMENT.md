# DEPLOYMENT.md — Splug Production Deployment Guide

This document contains step-by-step checklists for deploying **Splug Electronics** to production on **Vercel**, **Supabase**, **Paystack**, **Mailgun**, and **Google Cloud OAuth**.

## 1. Vercel Deployment Checklist

### Step 1: Connect Repository
1. Import your GitHub repository into [Vercel](https://vercel.com/new).
2. Framework Preset: **Next.js**.
3. Root Directory: `./` (or project root).
4. Build Command: `next build` (or leave default).
5. Output Directory: `.next` (leave default).

### Step 2: Environment Variables
Add all required environment variables in **Project Settings → Environment Variables**:

| `NEXT_PUBLIC_APP_URL` | Public canonical application URL | `https://splug.ng` or `https://splug.vercel.app` |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase Project URL | `https://qnjrvsigzdkazghsqfjr.supabase.co` |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Supabase Anon Key | `eyJhbGciOi...` |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase Service Role Secret (Server-only) | `eyJhbGciOi...` (Never expose in browser) |
| `NEXT_PUBLIC_PAYSTACK_PUBLIC_KEY` | Paystack Public Key | `pk_live_...` (or `pk_test_...`) |
| `PAYSTACK_SECRET_KEY` | Paystack Secret Key (Server-only) | `sk_live_...` (or `sk_test_...`) |
| `MAILGUN_API_KEY` | Mailgun API Secret Key | `aceb7450...` (or live domain key) |

## 2. Supabase Production Checklist

### Step 1: Database Schema & Migrations
Ensure the complete schema and all security policies are active:
- The compiled schema file is committed at [`supabase/full_schema.sql`](file:///c:/Users/HP/Desktop/Splug/supabase/full_schema.sql).
- Run it in the **Supabase Dashboard → SQL Editor** for your production database.

### Step 2: Seed Electronics Catalog
- Execute [`supabase/seed_products.sql`](file:///c:/Users/HP/Desktop/Splug/supabase/seed_products.sql) in the SQL Editor to populate initial verified electronics inventory, variants, categories, and brands.

### Step 3: Storage Buckets & Policies
1. In Supabase Dashboard → **Storage**, create bucket: `product-images`.
2. Set Public Bucket: **Enabled** (for public read access to product photos).
3. Confirm RLS policy: Public `SELECT` allowed; `INSERT`/`UPDATE`/`DELETE` restricted to administrators (`is_admin()`).

### Step 4: Authentication Redirects
1. Go to **Authentication → URL Configuration**.
2. Set **Site URL**: `https://your-domain.com`.
3. Add **Redirect URLs**:
   - `https://your-domain.com/auth/callback`
   - `https://your-domain.com/**`
   - `http://localhost:3000/auth/callback` (for local development)

### Step 5: Grant Admin Privileges
To access the `/admin` Operations Control Center:
```sql
INSERT INTO public.user_roles (user_id, role)
VALUES ('<YOUR_AUTHENTICATED_USER_UUID>', 'admin')
ON CONFLICT (user_id, role) DO NOTHING;
```

## 3. Paystack Live-Mode Checklist

### Step 1: Switch Keys
1. In your [Paystack Dashboard](https://dashboard.paystack.com/), toggle from **Test** to **Live**.
2. Copy `pk_live_...` and `sk_live_...` to Vercel production environment variables.

### Step 2: Configure Webhook Endpoint
1. Go to **Settings → API Keys & Webhooks** in Paystack.
2. Set **Live Webhook URL**:
   ```
   https://your-domain.com/api/webhooks/paystack
   ```
3. Verify that your webhook endpoint uses raw payload HMAC SHA-512 signature validation (already built into `src/lib/paystack/signature.ts`).
4. Ensure the endpoint returns HTTP 200 immediately to confirm webhook delivery.

## 4. Mailgun Custom Domain Checklist

### Step 1: Add Custom Domain
1. In the [Mailgun Dashboard](https://app.mailgun.com/mg/sending/domains), click **Add New Domain** (e.g. `mg.splug.ng` or `splug.ng`).
2. Select your domain region (US / EU).

### Step 2: Configure DNS Records at Domain Registrar
Add the DNS records generated by Mailgun:
- **TXT (SPF)**: `v=spf1 include:mailgun.org ~all`
- **TXT (DKIM)**: `k=rsa; p=...` (name: `k1._domainkey.mg.splug.ng`)
- **MX (Incoming)**: `mxa.mailgun.org` (Priority 10) & `mxb.mailgun.org` (Priority 10)
- **CNAME (Tracking)**: `mailgun.org` (name: `email.mg.splug.ng`)

### Step 3: Verify DNS in Mailgun
1. Click **Verify DNS Settings**. Once verified, status will turn **Active**.
2. Update `MAILGUN_DOMAIN` in Vercel to your custom domain.
3. Update `MAILGUN_FROM_EMAIL` to `Splug Orders <orders@mg.splug.ng>`.
4. Outgoing emails will now deliver to all email addresses without needing authorized recipient invitations.

## 5. Google Cloud OAuth Checklist

### Step 1: Google Cloud Project & Consent Screen
1. Go to [Google Cloud Console](https://console.cloud.google.com/).
2. Create or select your project.
3. Configure the **OAuth Consent Screen**:
   - User Type: **External**
   - App Name: `Splug Electronics`
   - User Support Email & Developer Email: Your contact email
   - Scopes: `openid`, `email`, `profile`

### Step 2: OAuth 2.0 Credentials
1. Go to **Credentials → Create Credentials → OAuth Client ID**.
2. Application Type: **Web application**.
3. Authorized JavaScript Origins:
   - `https://<YOUR_SUPABASE_PROJECT_ID>.supabase.co`
   - `https://your-domain.com`
4. Authorized Redirect URIs:
   - `https://<YOUR_SUPABASE_PROJECT_ID>.supabase.co/auth/v1/callback`

### Step 3: Supabase Auth Google Provider
1. Copy **Client ID** and **Client Secret** from Google Cloud.
2. In Supabase Dashboard → **Authentication → Providers → Google**:
   - Toggle **Google Enabled**: `ON`
   - Paste **Client ID** and **Client Secret**
   - Save changes.

## 6. Pre-Launch Smoke Test Checklist

- [ ] Unauthenticated user can browse homepage, catalog, search, and category pages.
- [ ] Product page displays correct variant pricing and options.
- [ ] Cart persists items in local storage for guest users.
- [ ] Sign-up / Sign-in creates profile in `profiles` and default `customer` role in `user_roles`.
- [ ] Guest cart merges seamlessly into Supabase database cart upon sign-in.
- [ ] Checkout recalculates totals authoritative server-side in minor units (kobo).
- [ ] Coupon validation verifies minimum order spend and expiration date.
- [ ] Paystack pop-up checkout initializes and redirects to `/checkout/success`.
- [ ] Atomic `finalize_payment` RPC increments order status to `paid` and decrements variant stock.
- [ ] Mailgun order confirmation receipt is dispatched to customer email.
- [ ] Customer account displays order details with real-time tracking timeline.
- [ ] Verified customer can submit reviews on purchased electronics products.
- [ ] Admin dashboard at `/admin` blocks non-admin users.
- [ ] Admin can update order status and trigger customer notification emails.
